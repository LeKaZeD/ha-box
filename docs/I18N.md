# Multilingual Support (i18n) - HA Box

## Overview

Multilingual support allows translating:
- **Configuration interface**: Labels and descriptions in Home Assistant
- **User messages**: Texts displayed on E-Paper screen, logs

## Operation

### Translation Files

Translations are stored in `translations/{language}.yaml` (ex: `fr.yaml`, `en.yaml`).

Home Assistant automatically loads translations according to the user interface language for labels/descriptions in `config.yaml`.

### Usage in Python Code

The `i18n.py` module (`core/i18n.py`) loads YAML translation files and provides a simple API:
- Automatic language detection (see order below)
- Translation loading from YAML files
- `get(key)` method to retrieve a translation

### Planned Languages

- **English (en)**: Priority

## Implementation

### Translation Files Structure

Translation files are located in `ha-box/translations/`:
- `en.yaml`: English translations
- `fr.yaml`: French translations

### Configuration Translations

Home Assistant automatically loads translations for `config.yaml` schema fields. The translation files include a `configuration` section that maps schema keys to translated `name` and `description` fields.

Example structure:
```yaml
configuration:
  display:
    name: E-Paper Display
    description: Configuration for the E-Paper display
    fields:
      enabled:
        name: Enable Display
        description: Enable or disable the E-Paper display
```

### Python Code Translations

The `i18n.py` module provides translation support for runtime messages:

```python
from ha_box.i18n import translate, get_translator

# Simple translation
message = translate("common.temperature", default="Temperature")

# Or use translator instance
translator = get_translator()
message = translator.get("common.temperature", default="Temperature")
```

**Note**: Runtime message translations (texts displayed on the E-Paper screen) are not yet implemented. The `i18n.py` module is in place for future use.

### Language Detection

The translator automatically detects language in this order:
1. HA Core config (`GET /core/api/config` → `language` field) — queried at startup
2. `LANG` environment variable
3. `SUPERVISOR_LANGUAGE` environment variable
4. Falls back to English (`en`)
